# Pixal3D-mv on one RTX 4070 SUPER (12 GB): first full runs, 2026-11-02

Agent pixal3d-eval-2, branch w/pixal3d-eval-2. Image `spl-pixal3d`, bf16 MV
weights, `--resolution 1024 --low_vram --max_tokens 32768`, seed 42.
GPU otherwise idle (199 MiB used by others, 0 % util before each run);
sidecar runs held `flock -x -w 300 ~/spl-work/gpu.lock`.

## Fixes needed to run at all

Official `inference_mv.py` (unmodified, `--low_vram`, sdpa) **OOMs on this
12 GB card even with the GPU to itself** (torus, 4 views: fails after 250 s and 234 s in two runs,
asking for 4 GiB in natten `fna_forward`). Two separate causes, both fixed
in `apps/image-to-3d/tools/pixal3d/sidecar/naf_lowmem.py` (patched in by
`run_mv.py`, exact, no change to the model):

1. Texture-stage NAF upsamples 1024-channel DINOv3 features to 1024x1024:
   resized values, na2d output and the rearrange copy are each 4 GiB fp32.
   Fix: run attention heads in groups (≤ 512 MiB) and project each group
   straight into the 64³ grid, so the full HR map never exists.
2. CuMesh (decode `fill_holes`, `to_glb` remesh) uses raw cudaMalloc and
   cannot see blocks the PyTorch caching allocator still holds. Fix:
   `torch.cuda.empty_cache()` before every CuMesh call; drop latents before
   `to_glb`.

## Generation (sidecar `run_mv.py`, 1024 cascade)

| input | views | load s | inference s | postprocess s | total s | peak VRAM | GLB |
|---|---|---|---|---|---|---|---|
| sphere | 1 | 161 | 187 | 160 | 508 | 10.47 GB | 986k tris, 2x 4096² webp, 34 MB |
| torus | 2 | 168 | 128 | 83 | 380 | 9.71 GB | 940k tris |
| torus | 4 | 170 | 125 | 73 | 368 | 9.82 GB | 949k tris |

The sphere run used the first fix version (head chunking without the fused
projection); torus runs used the final one. "load" includes weight loading
from disk and the NAF torch.hub download, paid per container start.

Khronos glTF validator 2.0 (npm `gltf-validator`): all three GLBs 0 errors,
0 warnings, 0 infos (only hint: BUFFER_VIEW_TARGET_MISSING).
Contact sheets (CPU point-splat, `render_glb.py`): closed, correctly shaped
surfaces; the torus reproduces the GT's 48x24 faceting.

## Geometry (synthetic primitives, `eval_object.py`)

GT = trimesh primitives rendered by `prepare_eval.py`; both meshes
normalised to the unit cube, prediction rigidly aligned (best of 24 cube
rotations + ICP; Pixal3D-mv outputs in frame-0's pose), 100k points each.

scans (no such GT exists on the GPU host yet), and metric conventions differ.
